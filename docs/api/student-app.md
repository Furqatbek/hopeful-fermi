# Student app — API by flow

Worked examples for the **student mobile app**, generated by performing each
flow against a real database and recording what came back.

`openapi/openapi.yaml` is the contract and remains authoritative for every field
and every type. This document exists because a schema cannot show a SEQUENCE,
and every flow that matters in this API is multi-step and stateful — starting an
attempt, spending the one audio grant, pairing for a speaking session. A client
built from the schema alone gets the shapes right and the order wrong.

**These examples cannot drift.** `tests/integration/test_api_examples.py`
re-performs every call in the ordinary test run, re-renders this file, and fails
when it no longer matches. If you are reading this, it matched on the last
commit. Regenerate with:

    WRITE_API_DOCS=1 python3 -m pytest tests/integration/test_api_examples.py

## Conventions

- **Base URL** — every path below is prefixed `/api/v1`.
- **Auth** — `Authorization: Bearer <access token>`. Access tokens last 15
  minutes; refresh with `POST /auth/refresh` and store the refresh token in the
  platform keychain.
- **Ids** — every public id is an opaque UUIDv7 called `xid`. Internal integer
  keys are never exposed. Treat an `xid` as opaque; do not parse a timestamp out
  of it.
- **Time** — every timestamp is UTC ISO-8601. Responses that matter for timing
  carry `server_now`; **the server is the sole authority on time remaining and
  on marking**, and the client's own clock is never trusted for either.
- **Errors** — RFC 9457 `application/problem+json`, always with a stable
  machine-readable `code`. **Branch on `code`.** `title` is prose and will be
  translated.
- **Idempotency** — `POST /attempts`, `POST /attempts/{xid}/submit` and
  `POST /orders` accept an `Idempotency-Key` header. Send one. A retry after a
  dropped response then returns the original result instead of doing the thing
  twice.
- **Values below are normalised** — ids, timestamps, tokens and digests are
  replaced with stable placeholders so this document is reproducible. Durations
  are preserved exactly: if `expires_at` is an hour after `started_at` here, it
  is an hour in production.

## Signing in

No passwords anywhere in this product. A student proves a phone number and keeps a rotating refresh token for months — every forced re-login costs an SMS.

### 1. Ask for a code

`POST /api/v1/auth/otp/request`

**Always `202`, whether or not the number has an account.** Anything else turns this into a phone-number oracle. The response says which channel was chosen — `telegram` is free and is picked whenever the account is linked, `sms` costs real money on every send, which is why the resend control is rate limited to five per hour per NUMBER and answers `429` with `Retry-After`.

Request:

```json
{
  "phone": "+998901234567"
}
```

Response `202`:

```json
{
  "challenge_xid": "019a0000-0000-7000-8000-000000000001",
  "expires_at": "2026-03-04T09:05:00Z",
  "channel": "sms",
  "resend_after": "2026-03-04T09:01:00Z"
}
```

`POST /api/v1/auth/otp/verify`

The access token is short (15 minutes) and the refresh token is long and rotating. Store the refresh token in the platform keychain, never in shared preferences: it is the credential that survives a restart.

Request:

```json
{
  "challenge_xid": "019a0000-0000-7000-8000-000000000001",
  "code": "123456"
}
```

Response `200`:

## What to do next

The four calls behind the home screen.

### 1. The profile

`GET /api/v1/me`

`is_minor` is derived server-side from a date of birth this endpoint deliberately never returns. It decides which speaking pools the student may enter and is not a preference.

Response `200`:

```json
{
  "xid": "019a0000-0000-7000-8000-000000000002",
  "phone": "+998901234567",
  "given_name": "Aziza",
  "family_name": null,
  "locale": "uz-Latn",
  "timezone": "Asia/Tashkent",
  "telegram_username": null,
  "target_band": null,
  "is_minor": false,
  "created_at": "2026-03-04T09:00:00Z"
}
```

### 2. What the centre has set

`GET /api/v1/assignments`

Order the home screen by `closes_at`. `mode` decides which runner opens — `exam` is timed, single-play audio, and the chrome must look different; `practice` replays freely. `allow_review_after` decides whether the answers screen is reachable once the paper is submitted.

Response `200`:

```json
{
  "items": [
    {
      "xid": "019a0000-0000-7000-8000-000000000004",
      "test_version_xid": "019a0000-0000-7000-8000-000000000005",
      "test_title": "Mock 1 v1",
      "cohort": null,
      "opens_at": "2026-03-04T08:00:00Z",
      "closes_at": "2026-03-11T09:00:00Z",
      "time_limit_seconds": 3600,
      "max_attempts": 2,
      "mode": "exam",
      "allow_review_after": "submit",
      "my_attempts_used": 0
    }
  ],
  "next_cursor": null
}
```

### 3. What this student may actually do

`GET /api/v1/me/entitlements`

The one table the whole product asks "is this allowed" against. A `402` anywhere else in the API means this list did not cover the action; render it as "not yours yet", never as an error.

Response `200`:

```json
[
  {
    "feature": "mock.unlimited",
    "subject_kind": "user",
    "source_kind": "order",
    "quantity": null,
    "remaining": null,
    "starts_at": "2026-03-03T09:00:00Z",
    "expires_at": null
  }
]
```

### 4. Band over time

`GET /api/v1/me/progress`

Empty for a student who has sat nothing. Design that state — it is the first thing most new users see.

Response `200`:

```json
{
  "attempts": 0,
  "latest_band": null,
  "best_band": null,
  "by_skill": {},
  "weak_types": []
```

## Sitting an exam

The flow the product exists for. Read this one in order — every step depends on the one before it, and two of them are irreversible.

### 1. Start the paper

`POST /api/v1/attempts`

**Send an `Idempotency-Key`.** A retry after a dropped response returns the same attempt rather than burning a second one against `max_attempts`. `server_now` and `expires_at` arrive together: compute the offset against the device clock once, here, and drive the countdown from it. Never trust the device clock alone.

Request:

```json
{
  "assignment_xid": "019a0000-0000-7000-8000-000000000006"
}
```

Response `201`:

```json
{
  "xid": "019a0000-0000-7000-8000-000000000007",
  "status": "in_progress",
  "mode": "exam",
  "attempt_no": 1,
  "expires_at": "2026-03-04T10:00:00Z",
  "server_now": "2026-03-04T09:00:00Z",
  "seconds_remaining": 3599
}
```

### 3. Enter a section

`POST /api/v1/attempts/019a0000-0000-7000-8000-000000000007/sections/1/enter`

Records the entry and is what makes the next call possible. `audio_locked` reports whether this section's single play has already been spent.

Response `200`:

```json
{
  "position": 1,
  "entered_at": "2026-03-04T09:00:00Z",
  "audio_locked": false
}
```

### 4. Mint the one audio grant

`POST /api/v1/attempts/019a0000-0000-7000-8000-000000000007/sections/1/audio-grant`

**In exam mode this succeeds exactly once.** The grant is tokenised to this user, expires in about two minutes, and a second call answers `409 audio_already_played`. Do not call it when the screen loads — call it when the student has committed to playing, because there is no way back. In practice mode the same call succeeds every time.

Response `200`:

```json
{
  "grant": "<media-grant>",
  "media_xid": "019a0000-0000-7000-8000-000000000011",
  "expires_at": "2026-03-04T09:02:00Z",
  "plays_remaining": 0
}
```

### 5. Autosave

`POST /api/v1/attempts/019a0000-0000-7000-8000-000000000007/answers`

The load-bearing endpoint, and **the response doubles as the clock sync** — which is why exam timing needs no WebSocket. Batch up to 200 deltas, send every few seconds and on every screen change. `client_seq` must increase per slot: a delta that arrives out of order is discarded rather than allowed to resurrect an older answer, which is what makes a retry after a network drop safe.

Request:

```json
{
  "deltas": [
    {
      "question_version_xid": "019a0000-0000-7000-8000-000000000008",
      "slot_key": "s1",
      "response": "bicycle",
      "client_seq": 1,
      "time_spent_ms": 8200
    }
  ]
}
```

Response `200`:

```json
{
  "accepted": 1,
  "rejected": [],
  "last_accepted_seq": 1,
  "server_now": "2026-03-04T09:00:00Z",
  "expires_at": "2026-03-04T10:00:00Z",
  "seconds_remaining": 3599
}
```

### 6. Submit

`POST /api/v1/attempts/019a0000-0000-7000-8000-000000000007/submit`

Idempotent: a retry returns the same score run rather than a second one. **There is a 30-second grace window after `expires_at`** — a submit that lands late is accepted and the overrun recorded, so do not refuse client-side at +1s. If the request fails entirely, retry with the same key; answers already saved are safe and the sweeper submits an abandoned attempt on its own.

Response `200`:

```json
{
  "attempt_xid": "019a0000-0000-7000-8000-000000000007",
  "score_run_xid": "019a0000-0000-7000-8000-000000000012",
  "status": "scored",
  "raw_score": 1.0,
  "max_raw": 3.0,
  "band": 5.0,

  "scored_at": "2026-03-04T09:00:00Z",

  "regraded": false
```
```json
}
```

## Speaking practice

Peer-to-peer voice practice, and the child-safety rules that wrap it.

### 1. Record parental consent

`POST /api/v1/me/consents`

**A minor may enter a public pool only while this is live.** Recording it with `granted_by_kind: self` is refused with `403 parental_consent_required`; the consent must come from a parent and carry contact details. `doc_version` pins which words were agreed to.

Request:

```json
{
  "kind": "stranger_matching",
  "doc_version": "2026-01",
  "granted_by_kind": "parent",
  "parent_name": "Dilnoza Karimova",
  "parent_phone": "+998901234567",
  "channel": "web"
}
```

Response `201`:

```json
{
  "kind": "stranger_matching",
  "doc_version": "2026-01",
  "granted_by_kind": "parent",
  "granted_at": "2026-03-04T09:00:00Z"
}
```

### 2. What has been agreed

`GET /api/v1/me/consents`

`revoked_at` is null while the consent is live. `doc_hash` is what makes this evidence rather than a boolean.

Response `200`:

```json
[
  {
    "kind": "stranger_matching",
    "doc_version": "2026-01",
    "doc_hash": "<hash>",
    "granted_by_kind": "parent",
    "channel": "web",
    "granted_at": "2026-03-04T09:00:00Z",
    "revoked_at": null
  }
]
```

### 3. Sessions this student may join

`GET /api/v1/speaking/slots`

**Server-filtered by age band.** A minor never sees an adult pool — this is enforced at the matching layer, not here, so do not implement your own filter. Show `age_band` and `audience` on every row: `public` means strangers and is the one that needed the consent above.

Response `200`:

```json
[]
```

### 4. Withdraw it

`DELETE /api/v1/me/consents/stranger_matching`

Immediate, and available to the student themselves — withdrawal only ever REMOVES capability, so it needs no friction. The row is kept: `granted_at` and `revoked_at` are the window a regulator asks about.

Response `204` — no body.

### 5. Or practise right now

`POST /api/v1/speaking/queue`

The live pool, matched in batches by a scheduled worker rather than on this call — so expect to wait, and design the waiting state properly. An entry older than ten minutes expires. Declaring a band range is optional; the matcher falls back to the student's measured band.

Request:

```json
{
  "band_min": 5.0,
  "band_max": 6.5,
  "language": "en",
  "org_only": false
}
```

Response `201`:

```json
{
  "xid": "019a0000-0000-7000-8000-000000000013",
  "status": "waiting",
  "joined_at": "2026-03-04T09:00:00Z",
  "estimated_wait_seconds": 900,
  "pool_size": 0,
  "suggested_slot": null
}
```

### 6. Leave the queue

`DELETE /api/v1/speaking/queue`

Response `204` — no body.

`GET /api/v1/speaking/ice-servers`

Two-hour TTL, per user. **The call is peer-to-peer and the audio never reaches our servers** — TURN relays only the connections that cannot be established directly. Fetch these immediately before connecting, not at app start.

```json
    }
  ],
  "expires_at": "2026-03-04T11:00:00Z"
}
```

### 8. Then open the socket

`POST /api/v1/realtime/ticket`

Single-use, 30 seconds, bound to this user. Browsers cannot set headers on a WebSocket handshake, so the access token must not go in the query string where it lands in every proxy log. The gateway burns the ticket on connect. Matching, session start and safety events arrive over this socket.

Response `200`:

```json
{
  "ticket": "<ticket>",
  "url": "wss://api.example.uz/realtime",
  "expires_at": "2026-03-04T09:01:00Z"
}
```

## Refusals you must handle

Taken live, not written from memory. Every one of these is a state your UI needs.

### 1. No token

`GET /api/v1/me`

**`403`, not `401`, and that is worth knowing before you write your interceptor.** RFC 9110 reserves `401` for missing or invalid credentials, but this API answers `403` with `code: unauthenticated`. A client that keys its refresh-and-retry on the status alone will never refresh, and will show "you do not have permission" for a token that merely expired. **Branch on `code`**: `unauthenticated` and `invalid_token` mean re-authenticate; any other `403` means genuinely not permitted.

Response `403`:

```json
{
  "type": "https://api.example.uz/problems/unauthenticated",
  "title": "Authentication required.",
  "status": 403,
  "code": "unauthenticated",
  "instance": "/api/v1/me",
  "request_id": "<request-id>"
}
```

### 2. A token that does not parse, or has expired

`GET /api/v1/me`

`403 invalid_token`. Refresh once and retry; if the refresh also fails, sign the student out.

Response `403`:

```json
{
  "type": "https://api.example.uz/problems/invalid-token",
  "title": "Invalid or expired token.",
  "status": 403,
  "code": "invalid_token",
  "instance": "/api/v1/me",
  "request_id": "<request-id>"
}
```

### 3. Not entitled, on the SELF-SERVE path

`POST /api/v1/attempts`

`402 payment_required`, and it is **not an error** — the student did nothing wrong and something is simply not theirs yet. `feature` names what was missing; route to the purchase screen.

**Only self-serve is charged.** An attempt started with an `assignment_xid` is never checked against the student: the centre paid for it when the work was set, and a student must never see a paywall for work their school assigned. So a `402` here always means "you chose this yourself and have not bought it", never "your homework is locked".

Request:

```json
{
  "test_version_xid": "019a0000-0000-7000-8000-000000000005"
}
```

Response `402`:

```json
{
  "type": "https://api.example.uz/problems/payment-required",
  "title": "No active entitlement for 'mock.unlimited'.",
  "status": 402,
  "code": "payment_required",
  "instance": "/api/v1/attempts",
  "feature": "mock.unlimited",
  "reason": "no_entitlement",
  "request_id": "<request-id>"
}
```

### 4. An id that matches nothing

`POST /api/v1/attempts`

`404`.

Request:

```json
{
  "assignment_xid": "019a0000-0000-7000-8000-000000000014"
}
```

Response `404`:

```json
{
  "type": "https://api.example.uz/problems/not-found",
  "title": "Assignment not found.",
  "status": 404,
  "code": "not_found",
  "instance": "/api/v1/attempts",
  "request_id": "<request-id>"
}
```

### 5. A minor consenting on their own behalf

`POST /api/v1/me/consents`

`403 parental_consent_required`. The asymmetry is deliberate: granting needs a parent, withdrawing does not.

Request:

```json
{
  "kind": "stranger_matching",
  "doc_version": "2026-01",
  "granted_by_kind": "self"
}
```

```json
{
  "type": "https://api.example.uz/problems/parental-consent-required",
  "title": "Stranger matching for a minor requires parental consent with contact details.",
  "status": 403,
  "code": "parental_consent_required",
  "instance": "/api/v1/me/consents",
  "request_id": "<request-id>"
}
```

### 6. A malformed body

`POST /api/v1/auth/otp/request`

`422`, and **every problem with the request comes back at once** in `findings` — each with a `path` you can attach to the right field. Do not make the student fix one thing per round trip.

Request:

```json
{
  "phone": "12345"
}
```

Response `422`:

```json
{
  "type": "https://api.example.uz/problems/request-invalid",
  "title": "The request body or parameters are invalid.",
  "status": 422,
  "code": "request_invalid",
  "instance": "/api/v1/auth/otp/request",
  "request_id": "<request-id>",
  "findings": [
    {
      "code": "123456",
      "severity": "error",
      "path": "body.phone",
      "message": "String should match pattern '^\\+998[0-9]{9}$'",
      "fix_hint": "Check the field against the OpenAPI schema."
    }
  ]
}
```

`GET /api/v1/attempts/019a0000-0000-7000-8000-000000000015/payload`

`404`, not `403` — the API does not confirm that an id it will not serve exists.

```json
  "status": 404,
  "code": "not_found",
  "instance": "/api/v1/attempts/019a0000-0000-7000-8000-000000000015/payload",
```
