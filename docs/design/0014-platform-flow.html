00How to read this

Every step is marked with what exists today, not what is planned.

  • Built Server and UI, working
  • Partial The gap is named on the line
  • Absent Not built — API or screen, but not both
Why the marks matter here

The recurring defect in this codebase is something declared in the API contract or a document and never implemented — or the reverse. One recent instance cost real data: GET /attempts/{xid} declared last_accepted_seq for months, the handler never returned it, and as a result every answer a student typed after refreshing the page was silently discarded.

So "it is in the contract" is never evidence, and this page does not treat it as such. Each claim was checked against the handler, or the component, or a running server.

Two actions exist purely to keep a student at your own centre out of something. view_exposure covers item statistics — a p-value tells a student which questions to spend time on. view_answer_key covers the answers themselves, and it exists because read cannot express the distinction: a student may read a published passage and must never read what it is marked against.

Two different walls

Keeping centre A away from centre B, and keeping a student at centre A away from centre A's teacher views, are different problems. Conflating them is easy, because both read org_id in actor.org_ids.

  • Tenant isolation is a content filter with four OR-ed visibility routes: platform-global, own-org, own private drafts, explicit grants. An out-of-scope resource is 404, never 403 — confirming a competitor's test exists is itself a leak.
  • Role separation inside one org is a policy check. The content filter will not do it: it is a visibility filter, and every student at the centre passes it.

02Stage one — building the library

Four asset types, each versioned, each org-scoped, each composed into papers by reference. Nothing is ever copied — that is what makes a bank a bank, and what lets one answer-key fix reach every paper using the item.

The seventeen question types

Question types are data, not code: JSON files overlaid by database rows, so a new type can be registered at runtime without a frontend deploy. Each declares its payload schema, key schema, scoring rules and an authoring form — and the console's question form is generated from that last one.

All seventeen reduce to three scoring primitives
PrimitiveTypesMarking
text_per_slot sentence_completion, summary_completion, note_completion, table_completion, form_completion, flowchart_completion, diagram_completion, short_answer Normalise, then compare to the accept list
choice_per_slot mcq_single, true_false_notgiven, yes_no_notgiven, matching_headings, matching_information, matching_features, summary_completion_bank, map_labelling Compare the chosen option id
set_selection mcq_multi Score per correct; over-selection scores zero
The most important fact about this product

Every one of the seventeen is Reading or Listening. There is no Writing or Speaking question type. Stage five returns to what that means.

Text answers run a normaliser chain before comparison — trim, collapse whitespace, casefold, strip punctuation, flexible hyphens, strip articles, UK/US spelling, number-words, ordinals, and contraction expansion for the prose types. This is why "thirty" and "30" both mark correct, and why a genuine missing alternative surfaces in item analysis instead of being buried in spelling noise.

Authoring without JSON — what a teacher actually types

The console used to ask for the question body and the answer key as JSON documents. Creating a matching-headings set meant typing {"slots": {"s1": {"accept": ["iv"]}}} into a textarea, and a group's option bank meant a line of A = Living near water per heading, numbered by hand. That is not a thing a centre admin between two classes can do, and every hand-typed identifier was a duplicate B or a skipped C waiting to reach a paper.

Four commits replaced it. The forms are still generated from the registry rather than switched on the type key — a type registered at runtime must stay authorable, which is the whole reason the authoring block is data — so what changed is the set of widgets with a real editor behind them, not the mechanism. Three ideas carry all of it:

  • Position assigns the identifier. Nobody types s1, and nobody types A =. A slot list is rows in order; an option bank is one option per line, lettered for banks and lower-case roman for headings, as a real paper does. A list pasted in with its letters attached is stripped and renumbered rather than refused, since pasting eight headings out of another window is the actual task.
  • Blank markers in the text derive the slot array. The author writes the line as the student will read it and the array the schema demands is computed from the markers, rather than typed a second time. Two lists that have to agree is a bug waiting.
  • The key editor is chosen by the type, and offers five controls: accepted alternatives per blank, a fixed picker drawn from the type's own options rather than a second copy of the list the scorer matches against, pick-one-from-the-bank, pick-several, and raw JSON for a widget nobody has written yet. The picker offers the question's own options and keys them by id — a key holding "Living near water" matches nothing a student can submit — while showing the words beside each letter, which is what an author chooses with. A type whose bank lives on the group is the exception: this form does not have the group in front of it, so those still take a typed letter, and the screen says so.

All seventeen types now ask for no JSON anywhere on the question form. The last three widgets went in together, because between them they were the only thing standing between a teacher and a publishable sentence completion.

WidgetTypesWhat it is now

Two were cosmetic. The blank editor was not

The payload schema for those three types requires a slots array as well as the text, and slots had no field on the form at all. The JSON fallback covered the body and nothing could produce the array beside it, so the console could emit only the text — which the write endpoint accepts, and which the publish gate then refuses with PAYLOAD_INVALID — 'slots' is a required property.

Driven end to end on a live stack, before and after: 201 on the question both times, that finding on the paper the first time and not the second. Three of the most common Reading types could not be taken from this console to a published paper, and the only sign of it was a finding on a paper, weeks of authoring later.

The array is derived from the markers now, the way the four structured-text builders already did it — the markers are the single source of truth, and a blank that exists in the sentence but not in the list is impossible rather than merely discouraged.

The answer key follows the body. A question whose payload declares its blanks gets one key row per blank, named "Blank 1", "Blank 2", and the manual add-a-blank control disappears. Counting them a second time was asking the author to restate a decision they had already made — and to restate it wrong: a two-blank sentence under a one-row key is a missing-slots finding at publish. This applies to every type whose payload carries slots, the slot lists as much as the prose.

Two smaller things the registry declares and the console had been ignoring: a field's written label, so it reads "Sentence" and "Information to locate" rather than text and statement; and its skills, so the audio cue appears on a listening question and not on a reading one.

The JSON fallback stays, and should: a type registered tomorrow with a widget nobody has written yet is then awkward to author rather than impossible, and the box names the widget it could not render. It is a fallback and not a plan, though, and the blank editor is why — behind a required field, or beside a required field with no form entry at all, it produces a question the write endpoint accepts and the gate refuses.

The group is a separate screen and a separate story. The registry's group form is read by nothing: /groups has its own hand-built editors for the rubric, the word limit and the option bank. That covers what a group needs except the image upload and hotspot placer a diagram or map wants — which is step 9, above, and why those two types still cannot be sat.

Copyright attestation — how liability is handled

Every passage, audio upload and import must carry an attestation. It is a required field, refused rather than defaulted, because a missing attestation that quietly becomes "original" manufactures a claim the uploader never made.

Claims are original, licensed (which requires a licence note), public_domain and permitted_excerpt. Nothing is pre-selected.

The record stores the claim, the SHA-256 of the exact statement text the uploader agreed to plus its key and version, the request IP and a hashed user-agent. Hashing the statement is what makes the row evidence: it proves what the wording said on the day, not what it says now. The attestation is recorded even when the import then fails to parse, because handing the file over is the moment the claim was made. The publish gate refuses material with no attestation or an open takedown.

Gap to close first

No attestation is captured for a question or a test, though the table permits both. A question stem typed straight out of a Cambridge paper leaves no evidence row anywhere.

Band maps — where a band actually comes from

A band map is a table of raw ranges to bands, plus a maximum raw. Lookup is first match wins. The console takes it as lines of 30-32 7.0. 

{ "max_raw": 40,
  "mapping": [ {"raw_min": 39, "raw_max": 40, "band": 9.0},
               {"raw_min": 37, "raw_max": 38, "band": 8.5},
               {"raw_min": 35, "raw_max": 36, "band": 8.0} ] }

Four validation rules, all reported at once:

  • Gap — every mark from 0 to the maximum must be covered. An uncovered mark yields no band at all: a whole cohort left unscored, silently.
  • Overlap — no mark covered twice. First match wins, so an overlap makes the later row dead.
  • Bands must fall in 0.0–9.0 in half-band steps.
  • Every row's minimum must not exceed its maximum.

Ownership decides who is affected. A map with no organization is the platform default that every centre inherits — creating one needs platform admin. A map with an organization is that centre's own curve, and this is the sanctioned way a centre tunes how strict it is.

Two limits worth knowing

One band map per test version. Per-skill maps exist only as a label: the scorer applies the same whole-test curve to each section's raw. Correct for a Reading-only paper; wrong for a multi-skill one.

A band map cannot be retuned. No endpoint creates a new version of one, so every map is permanently version 1. Retuning means creating a new map and pointing new test versions at it — existing published versions keep the curve they were frozen with, which is right for reproducibility.

The publish gate

Nineteen checks, run as a pure function of the composition tree and the type registry — no database. Every finding comes back at once with a code, severity, path, message and fix hint, deep-linked to the broken item, and is persisted so the author can close the tab.

Validate requires edit, not read — findings quote accepted answers verbatim, and read is granted to every student at the centre.

Review, publish, and the snapshot

Review is per-centre and off by default, on the grounds that most centres here are one or two people. When it is on: the gate runs first, so a broken paper cannot be submitted; nobody approves their own work, barred for both the submitter and the version's creator; the approval fingerprint covers answer keys, so approve → edit → publish is refused as stale; and approval is not a deploy — an approved version waits until someone presses Publish.

Why the snapshot exists

Publishing materialises the entire resolved student-facing tree into one JSON document. Serving a paper becomes one row read instead of a nine-table join, on every request, for every student in a hall. It is also what makes a sat paper immutable: the student sees exactly the document frozen at publish, whatever happens to the library afterwards.

It carries no answer keys and no transcripts. It is the document that goes to the device.

Immutability after publish is enforced twice: a check on every composition endpoint, and a database trigger refusing any change to the version's title, config, band map, question count, maximum raw or checksum. Application discipline is not relied upon.

Step 3 used to be the biggest hole in the product

The only code path that created a user was Telegram verification, which neither client calls: signing in by code never registers, and accepting an invitation requires already being signed in. A centre could be created, a class filled and a paper published, and not one student could get in.

Redemption closes it. The invite is the authority — issued by someone with manage_org, bound to one number, expiring, stored as a hash — and the one-time code proves the caller holds that number. Neither is sufficient alone, so a forwarded link is worth nothing: whoever opens it can prove their own number and gets invite_not_yours. The invite is checked before the code is spent, so a bad token cannot burn attempts against a real student's challenge.

The student app opens it from ?invite=<token>, read before the sign-in gate — a brand-new student has no session, so a route behind that gate would be the one screen they cannot reach. The token is stripped from the URL on success.

What is still missing

Nothing delivers the invitation: the admin passes the link by hand. And the code endpoint sends nothing to a number with no account — deliberately, so it is not a phone-number oracle. Under pilot mode the code comes back in the response and the screen shows it, which is no worse than sign-in: there is no SMS provider at all, so the pilot flag is the only delivery that works for anyone. Before it is switched off, the notification pipeline must be able to address a bare phone.

Steps 8b and 9 — one unread column killed the seats

A seat licence is the narrower grant, not the stronger one: every other kind covers every member of a centre, while a seat covers only the students the centre has seated against it. That distinction lives entirely in one string, source_kind = 'seat' — and nothing wrote it. Not the payment path, not the grant endpoint. So the whole seat subsystem read a row no code could produce, and the per-student coverage check quietly degenerated into “the org holds the feature”.

The cause was a column selected nowhere. A product's kind has allowed seat_licence since the billing migration and decided nothing; the grant path wrote 'order' for every purchase alike. A centre buying ten seats entitled all four hundred of its students — the exact failure the entitlements module names in a comment two lines above the branch that was supposed to prevent it. The billing suite's own fixture sold a seat licence and asserted the wrong answer.

Granting the same thing by hand is now possible too, on the panel that already knew how to revoke — whose empty state read “no seat licence has been granted” while offering no way to grant one. A hand-granted seat is held to what the seat subsystem can use: an organization, a mock-sitting feature, and a count. A seat the lookup cannot find covers nobody for ever while reading as granted.

And what a purchase now actually buys

Two more columns in the same row were documented and never interpreted. A product's features is JSON whose shape the migration writes down in its own table definition — [{"feature": "mock.unlimited"}, {"feature": "competition.entry", "quantity": 4}] — and the grant loop stringified it, producing an entitlement for a feature literally named {'feature': 'mock.unlimited'}: a valid row behind a green order that the access check could never match again.

And a subscription now grants no quantity at all, because quantity means “a consumable balance” and a subscription's bound is its expiry. Writing 1 there made every monthly subscriber's unlimited mocks a single use — harmless only while nothing spent anything, and a live defect the moment the consume path acquired its first caller, which it now has.

The B2B model in one line

The centre pays when the work is set; the student is never charged. That is why starting an assigned attempt deliberately does not re-check entitlement.

05Stage four — sitting the paper

The governing rule: the server is the sole authority on time and on scoring. The client is trusted with neither.

Every response that could plausibly carry time returns the server's clock, the deadline and the seconds remaining, so the client renders a countdown from a delta and never from the device clock — which on a cheap handset can be minutes out. It is also why exam timing needs no WebSocket.

Sign-in

  • Five codes per phone per rolling hour, counted in PostgreSQL rather than the Redis limiter. That one fails open so a Redis restart cannot end a student's exam; this one spends real money and must fail closed. Per phone rather than per caller, so an attacker rotating IP addresses gets no fresh allowance.
  • The request endpoint always answers 202, even for an unknown number. Anything else turns it into a phone-number oracle.
  • The refresh token never enters the response body — it is an httpOnly, strict-same-site cookie scoped to the auth path. The access token lives in memory only.
  • In pilot mode the code is returned and shown on screen, loudly labelled as account-takeover-by-design, because there is no SMS contract yet. It disappears when the flag is off, with no code change.

Starting, and resuming

Starting an attempt on an assignment returns the attempt already in progress rather than opening a second one. Resuming is not a new attempt and does not count against the limit.

The part that was broken, and why it mattered
  1. The state endpoint returns the saved answers and the sequence number each was accepted at.
  2. The client repopulates the fields and seeds its per-slot counters from those numbers.
  3. Without step 2 the counters restart at 1, the server discards any delta not strictly above what it holds, and every answer typed after the refresh is rejected as stale — invisibly, because a failed flush deliberately shows the student nothing.

Restored answers merge under anything already typed, so a slow resume can never overwrite a keystroke.

Autosave — the load-bearing endpoint

A keystroke reaches IndexedDB before it reaches the network. The outbox is the record; React state is the rendering.

  • Batched every 7 seconds, plus when the tab is hidden or the page is closing — the moments a session is most likely to be killed without warning.
  • Sequence numbers increase per slot. The server drops anything at or below what it holds, so an out-of-order arrival on a flaky link cannot resurrect an older answer. This is what makes a blind retry safe.
  • An idempotency key per flush, so a retry after a timeout replays the stored response rather than applying the batch twice.
  • Partially acceptable by design. One malformed answer must never cost a batch of forty; the other thirty-nine belong to a student sitting an exam right now. Rejections name the question as well as the slot, because every question in a paper has an s1.
  • The response is the clock sync. Every successful flush re-anchors the countdown for free.

Verified live: with the network cut, three answers were typed and held, no false alarm was shown, and all three were accepted on reconnect.

Listening

The player mints the grant on the student's click, never on mount — in exam mode the call succeeds exactly once, so spending it because a component rendered would burn the play on someone who opened the section to read ahead.

Why the whole track is downloaded first

A grant lives about 120 seconds; a section is half an hour of audio. Handing the grant URL straight to an <audio src> works for roughly two minutes and then 403s on the next range request — with no way to re-mint, because the play is already spent. The section would die mid-sentence and be unrecoverable.

One fetch() held open has no such problem: the grant is checked when the request starts. So the bytes go to a Blob and playback is immune to the network from then on.

Exam mode renders no transport controls — the real test gives none, and a seek bar is a different exam. If the browser refuses to start playback on its own, which is likely on a first visit, an explicit Start playing button appears rather than leaving a loaded recording with no way to start it and a clock running.

Verified live: grant minted, 352 KB streamed (200 full, 206 on range), a playable WAV decoded, playback running with the top bar's volume applied, and a second grant refused 409 audio_already_played.

Review

The review endpoint returns, per slot: the verdict, the points, what the student wrote, what it normalised to, every accepted answer, which alternative matched, the normaliser chain that ran, and — for listening — the transcript at the moment the answer was spoken.

/review/:xid renders it against the paper itself, so a student re-reads the question with their own answer in it rather than a bare list of verdicts. Two requests: review is the marking, the payload is the questions.

The refusals carry most of the value

Four things can legitimately withhold this screen, and each is a different sentence with a different thing to do next: the centre chose not to release answers; the assignment has not closed yet (with the date it opens); a competition on the same paper is still live (with the time it ends); or it is not marked yet. A student told only "Forbidden" asks their teacher, who asks you.

Two details worth knowing. A set answer is reported under the slot key selection — the scorer's own name for the whole item, matching no slot the question declares — and the client maps it onto the question's first slot; without that a multi-select renders with nothing ticked directly beneath the words "You wrote B, C". And the transcript is withheld while the same student has a live attempt on that audio, whoever's review is being read.

Submitting

  • The client flushes the outbox first, or the last thing typed is never marked.
  • A late submit is accepted, with a 30-second grace window; the overrun is recorded and never penalised. The worst outcome of trying is a marked exam; the worst outcome of not trying is an unmarked one.
  • Idempotent by key and by state — a retry returns the same score run.
  • Answers are frozen by a database trigger, not by application discipline.
  • Marking is synchronous: the band exists the moment the student submits.

06Stage five — marking, bands, and what a teacher can change

A teacher cannot set a band by hand.

There is no marking screen, no rubric, no score override and no manual band entry anywhere in the product. This was verified by enumerating every path in the API — and it is not an oversight to work around. It follows from the design: all seventeen question types are Reading/Listening, a Writing section cannot even be authored, and Speaking today is peer practice, not assessment — slots, bookings, pairing, connection credentials and a safety report, with no examiner and no band.

If your plan includes marked Writing, treat it as unbuilt, not partly built. It needs a writing question type, a long-form answer surface, a rubric model, a marking queue, a marker role, and a per-criterion band entry path. None of that exists.

How a band is actually produced

score = f(responses, key_versions, band_map_version, engine_version)

A pure function. Items dispatch by scoring primitive, never by question type. Awarded points sum into a raw decimal; the raw is rounded to a whole number and looked up in the band map.

Every pass writes an immutable score run carrying the engine version, the band map version, and the exact map of question to answer key used. That is what makes a mark reproducible, and what makes a regrade a recomputation rather than a mutation.

Two behaviours to know: a missing key voids the item rather than failing the student, and a raw the band map does not cover yields no band while the run still scores — which is why gap validation matters.

8A finished contest? A platform admin decides/regradesBuilt
9Apply/regradesBuilt

Invigilation authorises on a teaching role at the assignment's centre — deliberately not plain membership, because the response carries every classmate's live band. Time left comes from the server's clock, never the invigilator's.

Marking shows, per slot: the verdict, points awarded and available, the raw response, the normalised response, the accepted answers, which alternative matched, and which normalisers ran. Every staff read writes an audit row. Note that the review setting binds the student, not the staff room — a teacher who chose "never" has not blinded themselves to their own class's marking. But a live competition on the same paper blocks review for staff too, because a contest can be cross-centre and a coach reading the key mid-contest is exactly the leak that gate exists to close.

Diagnosis is the only diagnosis the product supports. A negative discrimination — the strongest students getting an item wrong — is the strongest automated signal of a wrong key in the system. Nothing is flagged below twenty responses, because flagging on noise trains authors to ignore flags.

The regrade flow

stage (dry run)   →   read the impact   →   apply
  • The dry run writes nothing to any score. It recomputes every affected attempt in memory and persists only counts.
  • Status becomes ready, deliberately not completed — a dry run that reports itself finished is one a tired admin assumes was applied.
  • Students to notify equals bands changed, by definition. Notifying on every raw-score wobble trains students to ignore the channel you need for what matters.
  • A reason is mandatory in the console even though the server would accept an empty one: it is the only record of why finished exams were rescored.
  • Apply recomputes from scratch, writes a new score run, supersedes the old one, and notifies each student whose band moved. Previous runs are retained, so the history still shows what they were originally marked.
  • A finished competition's ranking cannot be moved by a centre. It needs a platform-admin decision with a rationale, and republishing needs a public notice. This is not a disabled button: the centre whose students are ranked is not the party to decide whether their ranking moves.

07UI guidelines

Two apps, two deliberately different visual languages, one shared stance: large-screen first, and a control the server would refuse is absent with the reason written beside it, never disabled.

The admin console — Bento Grid × Soft Minimalism

Ground rule: the page is not white. A faintly cool grey ground with white compartments floating on it is what makes a bento read as separate boxes rather than ruled sections of one sheet. Pure white on white needs a hard border to show the seam, and hard borders are what this style avoids.

Colour

  • --ground#f4f5f7
  • --surface#ffffff
  • --ink#16181d
  • --muted#6b7280
  • --line#e8eaee
  • --accent#5457d6
  • --accent-soft#eeeefc
  • --danger#c0392f
  • --good#2f8659
  • --warn#9a6614

One accent, low saturation. Indigo rather than a primary blue, because it stays calm over the large flat areas a sidebar creates.

Dark mode follows the operating system and nothing else. There is no theme switch, which is why a screen captured on a light machine and the same screen on a reader's dark one are not the same picture. The relationship is the same two-tone one, kept soft: near-black would make the compartments float on a void.

A colour scheme is not a colour token

color-scheme is declared alongside the tokens and answers a different question from them. The custom properties restyle what the stylesheet draws; color-scheme restyles what the browser draws for itself — checkbox and radio glyphs, the select arrow, scrollbars, the date picker. It was never declared, so those stayed in light mode on a dark page: white checkboxes on a near-black surface, the brightest thing on the screen and attached to the quietest control on it. No token sweep finds this, because there is no token to sweep.

Space — a 4px base, used as a scale rather than by eye

  • s1 · .25
  • s2 · .5
  • s3 · .75
  • s4 · 1
  • s5 · 1.5
  • s6 · 2
  • s7 · 3

The single biggest reason an interface reads as "designed" is that its gaps agree. Radii follow the same logic and are larger on containers than on the controls inside them — which is what makes a compartment look like it holds things: .5 / .75 / 1 / 1.25rem, plus a pill.

Shadows are two very low-opacity layers: a tight one for the edge and a wide one for the lift. A single dark shadow is what makes card designs look cheap.

Type

Self-hosted Inter (variable 400–700) in three subsets — latin, latin-ext, cyrillic — 152 KB total. Self-hosted rather than a CDN because the audience is on Uzbek mobile data and a third-party font is a third-party outage. Tabular figures are switched on per element where numbers must line up, not globally, because proportional figures read better in prose.

Navigation — eight rules, each pinned by a test

  1. The group holding the current page opens by itself, on load and on every navigation — including one the sidebar did not start.
  2. A closed group containing the current page shows a small accent dot. That is the compensation for the accordion hiding four-fifths of itself.
  3. Never two groups open at once. The state lives in the click handler, not an effect, so it is never briefly wrong.
  4. A closed panel is made inert — hiding overflow alone would leave the links keyboard-focusable.
  5. Active matching is longest-path-first, then a nested table maps version pages onto Tests and invite pages onto Account.
  6. The Platform group is removed entirely, not disabled, for non-admins.
  7. Writing is deliberately absent — there are no Writing screens and no marking engine. A test fails if anyone adds it.
  8. No group may exceed seven items. Library sits at the cap.

The accordion animates its grid rows from 0fr to 1fr rather than a maximum height, so easing runs against real content height and nothing is clipped. Reduced-motion preferences kill it. There is exactly one breakpoint in the whole stylesheet, at 60rem, below which the sidebar becomes a drawer that closes itself on navigation so it cannot cover the page just requested.

Link colour rule. Links take the accent and underline on hover only — but inside a table cell they take the ink colour at a heavier weight, earning the accent only on hover. Forty blue links down a column would make the most-read cell the loudest thing on the page.

Controls — measured, not eyeballed

Every rule below went in after measuring a rendered screen. None of them was visible by reading the stylesheet, and each had shipped.

  • A row is a flex line, so "inputs flex to fill it" filled it — and a checkbox is an input. A tick box grew to forty rem with its label stranded at the far end. Text fields flex; checkboxes and radios do not grow and do not shrink, because they are glyphs, not fields.
  • A fieldset is a list of choices, so it stacks with a gap. As a plain block it gave three toggles nothing but line-height between them, and three separate decisions read as one paragraph.
  • A label is a block with the field's own margin after it, so a form reads label-over-field down the page rather than as a run of inline words.
  • The link style was written for <button> alone, so every anchor styled as a link kept button padding, a border and the wrong size — most visible in tables, where a cell link also has to give up the accent colour.
  • A component stylesheet may not name a global token. A local --warn shadowed the global one for everything nested beneath it, turning a chart's bars an unrelated colour. Local names for local meanings.
  • A form is a flex column, so it stretches its children across the cross axis. A bare link — one not inside a row — came out 990px wide with its label centred in the middle of the page, reading as a heading rather than something you can press. Sized to its content, not aligned to the start, which would also un-centre the links that sit in a row beside a full-size button.
Currently dead

The Bento grid itself — the grid class, the cell classes and the span custom property — is fully specified, ships in the production bundle, and is referenced by zero components. Every screen is a flat vertical stack. The tokens above are real and in use; the grid is not.

The student app

Two visual languages on purpose: a drill surface (sign-in, home, result) in bento cards, and an exam runner that imitates the real computer-delivered client.

The line we do not cross

We copy the interaction design, never the brand. Familiarity is what produces transfer to the real test; brand identity invites a letter. A student must find the layout familiar and must never mistake this for the official test.

The exam shell

A fixed, non-scrolling three-region grid. Allowing the middle row to shrink below its content is load-bearing — without it the panes stop scrolling and the whole page silently becomes a scrolling document that loses the fixed timer.

RegionContents
TopCandidate and section (left) · timer, centred · Settings (right)
BodyReading: passage left, questions right, draggable divider
BottomReview flag (lower-left) · question palette · "n left" · Finish
  • The timer is top-centre and flashes at 10 and 5 minutes. Tabular figures, so the width does not jitter as digits change — a clock that shifts its neighbours every second is hard to ignore, and this one is already deliberately hard to ignore.
  • A flashing clock is exactly the pattern that triggers migraine, so reduced-motion keeps the colour change and drops the flash.
  • Answered questions are underlined, not filled. A filled marker and a circled one compete for the same glance; an underline sits under the shape and reads independently of it.
  • Review turns the palette square into a circle — the only thing the flag changes.
  • Highlighting is select → right-click → highlight or clear all.
  • Four colour themes; "Standard" is black on a pale blue-grey, not white — a full-white page at exam brightness is fatiguing over three hours.
  • Three text sizes are zoom multipliers — 1.0 / 1.2 / 1.4 — applied to the root, with every length in rem, so the whole interface scales rather than body copy alone.
  • At zero the paper auto-submits and keeps the answers.

The four themes

  • Standard#eef2f8 / #14171a
  • Inverse#0b0e11 / #f2f4f6
  • Cream#f3e9d6 / #22201b
  • Yellow on black#000000 / #ffd400
  • --accent#1f5fa9
  • --highlight#fff2a8
Every theme must redeclare every semantic colour

The two dark themes did not. --warn and --danger were left at the light theme's dark orange and dark red and carried straight onto a near-black page — measured against the pane: 3.71 and 2.83 in Inverse, 3.94 and 3.01 in Yellow on black, against the 4.5 the rest of the sheet clears.

These are not decorative. --warn is the timer at ten minutes left and the word limit that decides whether an answer is marked wrong; --danger is the timer at five minutes and the "incorrect" verdict on review. The least readable text on the page was the text that costs a candidate marks — and Yellow on black is the theme a candidate chooses because they cannot read low contrast.

Now 8.98 and 9.32. --warn takes the palette's own yellow there, since that theme is deliberately monochrome and a stray orange reads as a rendering fault, and --danger stays amber rather than red: a red that clears contrast on black is pink, and the clock at five minutes is the one thing that must not be misread.

Question rendering, and one hard-won rule

One slot-based renderer. Prose splits on slot markers so an input sits inline in the sentence, baseline-aligned and sized in character units so it scales with the text setting. The word limit is shown beside the question number and is never enforced client-side — the scorer checks it against the raw answer and marks an over-limit answer incorrect outright, never truncated.

Why Finish lives at the far end of the bottom bar

It used to sit inline under the answer field, one Tab away from the gap being typed into — and tabbing between gaps is the ordinary way to fill these in, so the key that should move a student forward ended their exam instead, on Space or Enter, with no confirmation.

Distance in the tab order is the fix; the confirmation dialog is the belt to that braces. The timer reaching zero still submits without the dialog: a modal must never stand between an expired exam and its marking.

08What is not built

Nothing here is speculative — each was confirmed by reading the code. Read this before promising anything to a centre.

Blocks a paper from being sat at all

  • Partial Six of seventeen types have no layout — note, table, form and flowchart completion, diagram completion and map labelling — and fall back to labelled boxes.
  • Partial Matching headings answers only its first paragraph; the payload carries up to fourteen.
  • Partial The group instruction line is never rendered. The student never sees "Complete the sentences below" — only the derived word-limit badge survives.
  • Fixed Three types could not be published from the console at all — sentence completion and both summary completions. The blank editor derives the slot array the schema requires from the markers in the prose, so the payload the console builds is complete, and the answer key takes its rows from the same array. Verified end to end, before and after.
  • Absent Diagram and map questions cannot be sat — their questions can now be authored, but no image can be attached to the group, so the student would be labelling a diagram that is not there.

Missing screens for endpoints that work

  • Absent No student account, invitations or consents screen. A student must sign into the admin console to join their own centre.
  • Partial The console's own Invitations screen is orphaned — built and routed, with nothing linking to it.

Onboarding and billing

  • Absent No self-serve signup. An account needs an invitation from a centre; an organization needs a platform admin. A deliberate shape for a B2B pilot, but there is no consumer on-ramp.
  • Absent Invitations are never delivered — the admin passes the link by hand.
  • Partial No SMS provider at all. The transport raises, so the pilot flag is the only working delivery for anyone, and the notification pipeline cannot address a bare phone — which invited students need.
  • Fixed Seats are structurally dead — the licence kind the seat lookup requires is never written by anything. The grant path reads the product's kind now, and a seat can also be granted without a payment. See stage three.
  • Built A bounded entitlement is now spent. Registering for a competition takes an entry and withdrawing gives it back — an entry is spent while you hold a registration. Charged after the capacity check, so a full contest costs nothing, and only on the transition into registered, so a retried request does not bill twice. The entry records which entitlement paid for it, because a refund has to credit the row the unit came off rather than whichever pack looks best today.
  • Absent Self-serve assignments create a row with no targets: invisible to every student and a 404 on start.

Scoring and bands

  • Absent No manual band entry, no rubric, no marking queue.
  • Absent Writing and Speaking are not scored at all.
  • Absent A band map cannot be retuned — no endpoint creates a new version.
  • Partial Per-section bands apply the whole-test curve to each section's raw.
  • Partial A regrade silently truncates at 5000 attempts, despite a docstring claiming it chunks.
  • Partial The impact report never names the students. Per-attempt deltas are computed and discarded; only counts survive.
  • Partial The regrade notification's direction is computed from the raw score, so a pure band-map change tells every affected student their band went down.

Correctness issues worth fixing early

These are defects rather than absences, so they live in docs/known-issues.md with the reproduction for each and are not repeated here — two lists of the same eight things is two lists that drift. The shape of them, so you know whether to go and read it: an invigilation count that disagrees with the marking, a "scored" test that reads the band instead of the score run, a rejected autosave delta deleted from disk anyway, a fresh idempotency key on every flush retry, per-section time limits that are authored and gated and never enforced, an unkeyed item that vanishes from review, and a small-screen guard that hides the exam runner while it keeps running.

The one that was worst is fixed: an idempotency replay was not scoped to the user, so presenting somebody else's key with a body that hashed the same returned that person's stored response — on starting an attempt, another student's attempt. The lookup now reads the owner it had been storing since migration 0002, and 0029 widens the unique index to include it so a scoped lookup cannot turn the leak into a denial instead.

The newest gate, and why it was missing

The student app had no gate at all. Its tests — the clock, the autosave outbox, the marking display, the themes; 101 of them today — ran nowhere, and neither did its build, so a break in the exam runner would have reached a candidate before it reached anyone else. The target and its CI step went in together, because the parity gate fails a target that CI never runs. That is what keeps this from happening twice.
